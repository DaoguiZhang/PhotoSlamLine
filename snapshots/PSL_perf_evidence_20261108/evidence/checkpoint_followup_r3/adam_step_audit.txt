The difference is already present early (23-28 at frame 500), grows roughly
with the number of updates, and is identical across all six groups.  This is
not the signature of one group-specific tensor reset.  It is consistent with
optimizer calls for which Adam does not advance its per-parameter step (for
example no differentiable parameter contribution), but the current logs have no
per-iteration Adam-step record, so the exact cause is NOT established.

Code sites that can affect the relation (audit only, no optimizer change):
- GaussianModelLine::trainingSetup (gaussian_model_line.cpp:2237) creates Adam.
- replaceTensorToOptimizer (~2318-2340) carries stored step, or sets step(0) if
  no state exists.
- densify/clone/split state extension (~2600-2640) carries stored step and
  zero-extends moments.
- GaussianMapperLine::restoreRecoverySnapshot (~4974-5011) can rebuild state in
  diagnostic replay only.
- host increments only after optimizer_->step() (mapper ~3701 and ~4767).
- H selection and stage counters do not touch Adam state.

Do not call the difference "missed updates" without a per-step audit.  The
Adam moments and LRs are complete; only the counter relation is unresolved.
